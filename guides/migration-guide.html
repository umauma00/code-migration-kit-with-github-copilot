COPILOT MIGRATION / LOCAL IMPLEMENTATION

コードを移す仕組みと、
正しさを確認する仕組み

人間の承認、AIによる提案、プログラムによる実行を組み合わせて移行します。まず、それぞれの担当と本文で使う用語を確認します。

00 / TERMS & ROLES

AI Agentが案を考え、ランナーが手順を実行する

「AI Agent」はCopilotのAIに役割を与えた担当。「ランナー」は、このリポジトリのNode.js実行プログラムです。人間が移行の方針を決め、成果物を確認して工程を承認します。

本文で使う用語を確認する
Node.js
JavaScriptのプログラムを実行する環境。このキットのランナーが動く環境を指します。
CLI
ターミナルに文字のコマンドを入力して使う操作方法。利用者が工程を起動する移行CLIと、ランナーがAIを呼ぶCopilot CLIの2つが登場します。
ワーカー
ランナーから呼び出される、担当別のAI Agent。実装、意味のレビュー、ルールのレビュー、裁定、修正の5役があります。
オーケストレーター
会話で調査・計画・成果物の確認を支援する調整担当のAI Agent。各ファイルを処理するワーカーとは別の役割です。
アダプター
ランナーとCopilot CLIの間をつなぐプログラム。指示を渡し、返答を読み、決められたJSON形式かを検査します。
JSON / JSONL
JSONは名前と値を持つ構造化データ。AIの候補や指摘をこの形式で受け取ります。JSONLは1行ずつJSONを並べた形式で、CLIの応答イベントに使います。
対応表 / manifest
元ファイルと変換先ファイルの1対1の対応を固定する表。ランナーの保存先と処理単位を決めます。
証跡 / 完了記録
何を入力にし、何をレビュー・検証したかを残すデータ。生成したファイルだけでなく、現在の入力・出力とこれらの記録の一致も完了条件になります。
ハッシュ
ファイルなどの内容から計算する値。内容が変わったかを照合します。コードの意味が正しいかの判断は、レビューや検証が担います。
承認 / gate
次の工程へ進めるという、人間の確認を記録するもの。確認理由と、その時点の入力・出力・前工程の情報に結び付きます。
judge / build / smoke / parity
judgeは元テストと比較器の欠陥検出、buildは設定した全体検証、smokeは最小限の公開操作、parityは元テストの再実行と新旧比較です。検証範囲は案件のコマンド設定で決まります。

CODE MIGRATION KIT / GITHUB COPILOT

人間が方針を決め、AIが移植し、ランナーが証跡を残す

移行プロジェクトには準備から検証までの工程があり、その「04」の中で、ファイルごとの変換・レビューを繰り返します。

AI Agent — 分析・生成・判断ランナー — 実行・保存・検証人間 — 仕様・範囲・工程承認
具体例：付属のPython → JavaScript題材math_ops.pytext_ops.pymain.py数値・文字列・エラーを同じ公開出力で返す。

移行プロジェクト → 04 全ファイルの変換 → src/math_ops.py

実コードと期待値は付属題材に基づく。ここで追うAIの応答・指摘・裁定は、仕組みを説明するための例。クリックは移行コマンドを実行しない。

「完了」の後でも、根拠が変わればやり直す

承認はその時点の入力・出力・前工程の実行に結び付く。古いファイルや古い成功記録を流用しないための仕組み。

指示・実行コード・証跡は、それぞれ別の場所にある

prompts/ ＋ .github/agents/

工程の進め方と、Copilotの担当別の指示。会話側のorchestratorが準備と全体調整を支援し、00〜03・06は会話で分析・判断を進める。

scripts/ ＋ lib/

承認、ワーカー呼び出し、応答の検証、保存、レビューと修正、検証コマンドを実装する。

migration/ ＋ ported/

導入先に置く設定・ルール・対応表・証跡と、変換後ソース。導入時、ランナーはmigration-kit/に配置される。

このページはリポジトリの実装を説明するガイド。付属のオフライン題材は配線と比較器の動作を確認できるが、実際のCopilotによる移植品質や、実案件の検証範囲は別途確認する。
