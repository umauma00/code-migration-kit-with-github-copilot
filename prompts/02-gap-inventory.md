Write `migration/inventory.tsv` using the template. Every row names a source

Count relevant constructs mechanically and reconcile the inventory coverage.
Have two independent reviewers check the same classifier batch, including its
highest-risk classes. Supplementary disjoint sampling may follow those paired
batch reviews; it never replaces either review of a batch.

## Source as the only specification

With `preparationProfile: source-as-spec`, draft RULEBOOK and inventory from how the
source actually behaves, without the first-20-rows stop or paired batch audits.
Run one independent review of the whole package (cited source lines, RULEBOOK,
inventory, dependency map) in a separate context, fix its confirmed findings and
re-review only the fixed items once (one repair round; what is still contested
becomes UNKNOWN or an open finding, never fixed again), then show ONE
report for 00b–02 with links, review points (high-impact inferences, UNKNOWN rows
including the survey's `uncited` count and `unsurveyedOversizedFiles`, the
findings fixed in the repair round, open findings with their evidence) and
choices: proceed to migration (recommended), revise, pause (in auto mode, put the
same list into the record's note and continue without asking).
Only after the user's OK run `phase complete 00b,01,02 --note TEXT`, then `judge`.
See [source-as-spec](../docs/SOURCE-AS-SPEC.md).

## Before the survey: generated files and policies

Run these once, before the inventory survey (`P="node migration-kit/scripts/preparation_cli.mjs"`):

1. `$P generated-files --write` finds generated files mechanically (generator
   file names, `<auto-generated>`/`DO NOT EDIT` headers, project
   `LastGenOutput`/`AutoGen`, `.gitattributes linguist-generated`) with their
   generator input. Their census sites become GENERATED rows without a model.
   Report counts only; never ask the person to review the list. Each file is
   translated as ordinary code unless the person names a target generator for
   its input: `generated-files --regenerate FILE --how TEXT [--target PATH]`
   (refused without an input in the repository). The file then leaves the
   manifest, and build approval waits until its target exists; `--translate
   FILE` switches it back.
2. `$P policy-questions` lists the choices the source cannot decide (web UI,
   data access, session state, date/time, configuration, services, desktop UI,
   legacy encodings, generated inputs), each with evidence and a conservative
   option. Ask them in one `ask_user` call, recommending an option; record each
   answer with `$P policy-record --topic ID --answer TEXT`. In auto mode record
   the conservative option with `$P policy-record --topic ID --answer TEXT --auto`
   without asking.
3. After the census, `$P rulebook-coverage --sites migration/inventory-sites.tsv`
   lists constructs no rule covers, and `survey run --kind inventory --sites
   migration/inventory-sites.tsv --trial 3` classifies up to three sites per
   construct in a separate store and reports the UNKNOWN share per construct
   (`trial.decide`). Decide those constructs the same way (tag a hand-written
   rule `construct: NAME`), then run the full survey once.

## Delegate classification by scope

After the mechanical census (`migration/inventory-sites.tsv`: file, symbol,
source_construct), run `survey run --kind inventory --sites migration/inventory-sites.tsv`
and `survey merge --kind inventory --sites …`. Each scope's surveyor receives the
RULEBOOK, the scope's sources and its census sites; results are per-scope shards
merged by the existing inventory merge, which refuses an incomplete census. The
paired independent audits and the joint audit still follow. See [surveys](../docs/SURVEYS.md).
A file too large for one survey input, and rows whose citations stay invalid
after the one correction, finish as UNKNOWN/TODO(port) (`unsurveyedOversizedFiles`,
`uncited`) instead of stopping; trace them in the inventory review and report the
counts. Never stop or ask because of them.

When existing shards need a combined review candidate before formal publication,
use `preparation_cli.mjs inventory-preview --sites PATH --shards LIST`; then pass
its exact outputHash to `inventory-merge --expected-hash SHA256` after review.
Both operations share the same parser and renderer. Do not write another TSV
parser/merge helper or rerun survey just to create this candidate. Fix a local
helper's return-shape TypeError within authorized preparation work, preserving
validated shards; do not ask whether to skip the candidate or its checks.
